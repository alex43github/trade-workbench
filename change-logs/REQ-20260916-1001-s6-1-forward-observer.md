## 范围与验收标准

实现一个默认关闭、research-only 的 Stage-6 Forward Validation observer。目标链路为：

`EVENT_WATCH → HIGH_OPPORTUNITY_HIGH_FAILURE_COST → EDP → WAIT_15M_RECHECK → +15m snapshot → POST_EVENT_REPRICE_RISK_COMPRESSION/失败 → ACTIONABLE_REVIEW_CANDIDATE → 可选 PAPER/RESEARCH plan → 1H/3H/6H/12H/24H outcomes`。

硬约束：

- `ACTIONABLE_REVIEW_CANDIDATE` 不是交易许可；
- `EXECUTION_FORWARD_RESEARCH_ENABLED` 默认关闭；
- `NO_TRADING_ACTIONS = 1`；
- Stage5 scorer artifact 不可用，因此所有 Forward 事件显式 `UNAVAILABLE_ARTIFACT`，不得生成/拟合 `p_opp`、`p_sev` 或任何概率；
- 仅保存因果时点可见信息，+15m 不得提前执行，resolver 必须显式接收 as-of；
- append-only JSONL，无 UPDATE/DELETE 路径；支持 EDP 去重、重启恢复、immutable recheck/plan/outcome；损坏/不完整持久化行 fail closed；
- 与 `services/structure-radar/main.ts`、Binance Gateway、真实下单/通知路径隔离；
- 本任务不部署、不激活 observer，所以 Forward mature sample 必须保持 `N=0`。

关键实现：

- flag 默认 OFF；recheck delay 固定 15m；
- EDP 原始因果字段、缺失度、版本、精确价格/时间冻结；
- `scorerStatus = UNAVAILABLE_ARTIFACT`，构造与持久化边界均拒绝 synthetic probability-like 字段；
- EDP logical retry 忽略仅运行时生成的 `createdAt` 漂移，实现 eventId/dedupe 幂等，同时语义冲突 fail closed；
- +15m classification 显式映射为 `ACTIONABLE_REVIEW_CANDIDATE` 或 `RECHECK_FAILED`，二者均 `tradingPermission=false`；
- PAPER plan 只有在同 event 已有 EDP + actionable recheck 后才允许 append，且始终 `paperOnly=true`、`tradingPermission=false`；
- JSONL 对各 record kind 做结构/类型/literal/timestamp 校验，合法 JSON 但字段缺失同样 fail closed；
- outcomes 按 `(eventId, horizon)` append-only/idempotent；
- 不存在 update/delete API；restart 可恢复待 +15m EDP。

TDD hardening RED 实际证明并修复了四个缺口：

1. 相同逻辑 EDP 因 autogenerated `createdAt` 漂移被错误判为 conflict；
2. recheck 缺少明确 lifecycle state；
3. PAPER plan 未强制等待 actionable recheck；
4. valid JSON 但结构残缺的持久化行未 fail closed。

中间开发历史曾出现两个无敏感信息的临时哨兵文件用于原子树写入准备，后续正常提交已删除；最终 base→feature diff 不包含这些文件，未使用 force-push/reset 重写历史。
