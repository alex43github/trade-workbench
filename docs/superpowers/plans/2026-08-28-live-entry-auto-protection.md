# 实盘入场自动止损实施计划

> **执行原则：** 所有测试使用 fake gateway；不得在测试、构建、部署或调试时发送 Binance 真实订单。

1. **补充失败测试与持久化模型**
   - 新增直播入场成交同步、来源保护创建、参数快照和重启幂等测试。
   - 给实盘策略账本增加每腿成交来源/保护映射与可查询状态；迁移必须兼容已有数据库。

2. **实现成交对账与保护创建服务**
   - 按 Binance client/order ID 对账入场累计成交量，生成或更新来源成交批次。
   - 以策略配置快照创建 `WEB` / `TELEGRAM` 的 `MA_SL` 保护，保持来源数量隔离和幂等。

3. **让执行器使用策略参数并执行两段止损**
   - 复用现有 closed-candle 保护执行器，但从保护快照读取 MA/ATR 参数及 ATR 倍数。
   - 保留交易所仓位、数量精度、超时查单、双向模式与待对账防线。

4. **接入 VPS 调度与状态通知**
   - 保护调度先同步活跃入场订单成交，再执行活动保护。
   - 将保护状态和异常事件接入网站策略 API/卡片与 Telegram 回执。

5. **验证与部署**
   - 运行定向 Node 测试、类型检查、生产构建及 `git diff --check`。
   - 仅在验证通过后部署代码到 VPS，确认服务与定时器健康；不进行真实下单验收。
