# 网站与 Telegram 实盘入场自动止损设计

日期：2026-08-28

## 已确认目标

网站和 Telegram 创建的每一笔 Binance USDⓈ-M 限价入场单，成交后必须自动获得独立的动态止损保护。该保护以该笔来源订单为单位，而非仅按币种或当前合并仓位运作。

规则使用该策略选择周期的最新已收盘 K 线及创建时冻结的均线、ATR 参数：

- 多头：收盘价严格跌破 `MA - ATR × 倍数`；
- 空头：收盘价严格突破 `MA + ATR × 倍数`；
- 第一根连续失效已收盘 K 线：对该来源的剩余数量发送 `reduceOnly` 市价单，目标保留初始成交数量的 50%；
- 第二根连续失效已收盘 K 线：对该来源剩余数量发送 `reduceOnly` 市价单全部退出；
- K 线回到安全侧后，连续失效计数归零。

这是真实交易保护，不是展示性策略或提醒。调度、部署、测试不会创建实盘订单；只有已由用户确认创建并实际成交的 `web` / `tele` 入场单才会在满足条件后执行市价止损。

## 来源与编号

每个策略继续保留策略组号 `TW-L-S-*`，每条腿保留用户可见来源号 `web0001` 或 `tele0001`，并以 Binance 的稳定 `newClientOrderId` 及 `orderId` 完成对账。

成交时，系统为每条入场腿建立一份不可重复的保护来源记录，保存：

- 策略、腿、来源编号、Binance client/order ID 和成交批次 ID；
- 精确已成交数量、均价、方向和读取到的杠杆；
- 时间周期、SMA/EMA 类型与长度、ATR 长度、ATR 倍数、横向止损线（如已设置）的参数快照；
- 已处理的最后一根收盘 K 线、连续失效次数、剩余可保护数量和保护状态。

同一 Binance 单向持仓可能在交易所侧合并。执行前必须读取实际仓位，并将退出数量限制为“该来源账本剩余数量”和“当前交易所同方向持仓”两者较小值。若来源账本无法可靠对应当前仓位，状态改为 `RECONCILIATION_REQUIRED`，停止自动退出，绝不借用或卖出其他来源的数量。

## 执行流程

1. 实盘调度器轮询活跃的 `web`、`tele` 策略订单，按稳定 client ID 查询 Binance 最新订单及累计成交量。
2. 首次发现成交或累计成交增加时，写入对应来源的成交批次和 `MA_SL` 保护策略；重复轮询、重启和超时恢复均不可重复创建。
3. 对每个活动保护策略，仅在新的已收盘 K 线出现时按其参数快照计算边界并判断失效。
4. 触发时先持久化受控退出订单及稳定的 `webSL...` / `teleSL...` client ID，再发送 `MARKET` 保护单；单向模式带 `reduceOnly=true`，双向模式使用匹配的 `positionSide`。
5. Binance 超时先按 client ID 查询；不确定、拒绝、最小数量/名义金额不满足或账本不一致均转为待对账并记录脱敏原因，不会自动重试或改成其他价格/数量。
6. 保护状态、退出回执和异常写入事件账本，供网页与 Telegram 查询及告警使用。

## 用户可见状态

每条成交入场腿旁显示以下其中之一：

- `止损保护中`：已创建保护并正在监听下一根收盘 K 线；
- `已减仓 50%`：第一根失效已成功执行，仍监听第二根；
- `已止损退出`：第二根失效的剩余仓位已成功退出，或仓位已不存在；
- `‼️ 止损保护异常`：保护创建、成交对账、市场数据或下单任一步失败/不确定，展示可操作的脱敏原因并提示先对账。

策略组状态仍表示入场单的总体状态；保护状态必须逐腿显示，不能用“策略已提交”冒充“止损已生效”。Telegram 在成交后及保护异常时发送同样的来源编号和状态通知。

## 非目标与安全边界

- 不自动保护用户手动下单、未绑定的历史持仓或模拟交易；这些继续走显式的 `alex` 手动保护流程。
- 不修改杠杆、保证金模式，不撤销用户手动订单，不使用市价补入场。
- 默认止盈不在本次“补齐强制止损链路”的改动中扩大为新的自动行为；已有保护单保持原逻辑。
- 当网站/VPS、网关开关或交易所账户不满足实盘条件时，不伪装成已保护；必须显示异常状态。

## 验收

- Fake Binance 下，网站和 Telegram 各一笔部分/完全成交入场单均只建立一次来源保护；重启/重复轮询不重复建立。
- 多空分别验证首根 50%、第二根全部、恢复安全侧清零、同一根 K 线不重复下单。
- 验证策略的 MA 类型、MA 长度、ATR 长度和倍数从入场策略快照读取，而不是错误固定为 SMA30/ATR14。
- 同币种双来源合并仓位时，只允许来源账本以内的退出；数量不足进入待对账，不退出其他来源。
- UI 逐腿显示“保护中 / 已减仓 / 已退出 / ‼️异常”，Telegram 文本包含相同来源编号和异常原因。
- 全部测试使用 fake gateway；构建、部署和启动不产生真实订单。
