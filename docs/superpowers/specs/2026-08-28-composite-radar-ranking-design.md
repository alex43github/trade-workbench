# 综合榜多条件雷达设计

日期：2026-08-28  
状态：已确认，待实现  
产品性质：只读研究与提醒；不改变交易执行

## 目标

在市场雷达增加独立的“综合榜”。它只汇总每日定时扫描得到的可信筛选快照，找出同一币种在同一方向上同时命中多个条件的情形，按条件数量优先、信号质量次之排序，并以醒目的橙色或红色提示重点观察对象。

## 数据源与方向

每日 Asia/Shanghai 08:00 的维护任务完成后，依次取得本轮 MA30×OI、日线破底翻、Vegas、以及实时雷达的逼空和筹码条件。综合榜只使用本轮成功读取的数据；失败、演示、待接入、过期或数据不足的来源不产生条件。

| 条件 | 方向 | 纳入规则 |
| --- | --- | --- |
| MA30×OI 增仓 | 多头 | 最新 `ready` 快照中的候选 |
| 破底翻 / 破顶翻 | 多头 / 空头 | 最新日线 `ready` 快照中的候选 |
| Vegas 强势 / 弱势 | 多头 / 空头 | 本轮保存的 1h、4h、1d 已收盘 K 线排列；同方向多周期仍只算一个条件，但在说明中列出周期 |
| 逼空重点 | 多头 | 实时雷达为 `live` 且 `participation === SQUEEZE` |
| 筹码集中 | 中性佐证 | 实时雷达非 `AVOID`、Top10 持仓在 45%–85% 且非派发阶段；只能附着到已有多头或空头方向，不能单独入榜 |

通用“候选”A/B、风险否决、演示数据和 TradingView 补充信息不构成综合榜条件。多空条件绝不混合计分：例如同一币的 Vegas 多头与破顶翻空头分别形成两个方向记录，只有各自满足至少两个条件时才入榜。

## 权重、等级与提醒

入榜门槛为至少两个不同条件。排序键依次为：条件数、等级、质量分、币种。质量分只用于同一条件数内排序，且每类来源有上限，不能盖过“多条件优先”。

- `WATCH`：2 个条件，橙色高亮。
- `HIGH`：3 个条件，深橙色高亮。
- `CRITICAL`：4 个或以上条件，红色高亮。

每行必须显示方向、等级、总权重、命中条件和来源快照时间。Bark 仅在新综合键出现，或同一 `symbol + direction` 从较低等级升至更高等级时发送；使用 `notification_deliveries` 的去重键，提醒正文仅说明研究条件，不含下单暗示。

## 持久化与调度

新增 D1 表 `radar_composite_snapshots`，保存每轮状态、生成时间、来源时间、候选 JSON 和警告。综合快照通过 `GET /api/radar/composite` 只读返回最近一轮；生成函数可被 scheduler 直接调用，不接受浏览器自定义条件。

08:00 维护流程在现有 MA30×OI 与日线破底翻完成后，取本轮可用候选并刷新 Vegas 快照，再生成综合榜。任何单个来源失败只会写入 warning 并跳过该来源，不能中断其他扫描、原有快照、Bark 重试或主雷达。

## 界面

顶部筛选栏新增独立 `综合榜`，默认打开它；原先的总雷达改名为“全部雷达”。综合榜以卡片或表格显示，`WATCH/HIGH/CRITICAL` 分别采用橙、深橙、红色边框/徽章。无可用快照、扫描尚未执行或没有多条件命中时要显示明确说明和生成时间，不能伪造结果。用户可点击币种进入既有交易图表。

## 硬约束与验收

- 只读研究：不导入订单、策略执行、仓位、止损或 Binance gateway 交易模块。
- 只使用已收盘 K 线及现有服务器端快照；不把缺失数据视为条件。
- 保留所有既有筛选栏、原始排序和手动扫描行为。
- 单元测试覆盖同向合并、方向冲突隔离、中性筹码附着、两条件门槛、等级排序、去重/升级提醒和失效来源跳过。
- API/页面测试覆盖持久化快照、08:00 调度接线、标签文案、高亮等级和交易执行隔离。
