# Binance 统一网络出口与安全升级入口

## 目标

让网站在 VPS 上以一个固定公网 IP 稳定访问 Binance，同时让行情、币种搜索、雷达扫描和账户只读使用同一条受控出口。保留受保护的升级入口，方便查看部署版本和触发既定发布流程，但不从网页执行任意系统命令。

## 架构

网站和 `binance-gateway` 同机部署。网站服务端只连接 `http://127.0.0.1:8788`；网关持有 Binance 密钥并与 Binance 通信。网关仅允许本机回环访问，交易功能默认关闭。VPS 的公网 IP 是唯一需要添加到 Binance API 白名单的地址。

新增一个服务端公共市场请求适配器：

1. 已配置本机网关时，优先通过网关请求 Binance 公共接口。
2. 网关未配置时，使用直接请求，便于本地开发。
3. 两者都失败时，向调用方提供结构化错误（来源、状态码、建议操作），而不是把错误静默降级为演示数据。
4. 浏览器侧仍可作为仅本地展示的最后回退；定时扫描和提醒不依赖浏览器。

适配器将接管交易图表、合约搜索、雷达扫描、维护任务和连接探测中的公共 Binance 请求。私有账户请求继续只通过现有网关。

## 升级入口

设置页新增“部署与升级”卡片：显示应用版本、构建时间、网关连通状态和最近升级结果。升级触发只调用服务器预先配置的 Webhook URL，使用 `DEPLOY_WEBHOOK_TOKEN` 作为 Bearer 凭证；未配置时按钮禁用并说明原因。

网页不会保存 VPS SSH 密码、执行 shell、接收任意命令或暴露 `.env` 内容。实际更新由 VPS 上的部署服务（例如 GitHub Actions webhook、Coolify 或受限 systemd handler）完成；该服务自行执行 `git pull`、构建、健康检查和回滚。

## 错误与可观测性

市场接口返回统一的 `source`、`mode` 与安全可显示的错误摘要。前端在搜索和筛选失败时显示具体原因及建议：网关未配置、网关不可达、Binance 被拒绝或上游超时。密钥、令牌、完整上游响应和内部地址不发送到浏览器。

## 安全约束

- `BINANCE_GATEWAY_BASE_URL` 仅接受 `127.0.0.1` / `::1` 回环 HTTP 地址。
- 网关 token、Binance API Key/Secret 和部署 webhook token 只保存在 VPS 环境变量中。
- 网关防火墙仅开放网站需要的回环端口；不向公网暴露 8788。
- Binance 网关保持 `BINANCE_GATEWAY_TRADING=false`，除非以后明确启用并完成额外审批。
- 升级 webhook 使用短令牌、HTTPS 和来源限制；可撤销。

## 验收与测试

- 单元测试覆盖：网关优先、直接请求回退、结构化错误和 URL 回环校验。
- 合约搜索能从网关返回完整 USDT 永续合约列表。
- 雷达手动扫描失败时显示可操作错误信息。
- 设置页在未配置 webhook 时不允许升级；配置后仅发送固定 payload。
- `npm test`、类型检查和生产构建通过；本地健康检查返回 200。

## VPS 上线顺序

1. 租用带固定 IPv4 的 VPS，记录其公网 IPv4。
2. 在 Binance API 管理页只白名单该 IPv4，并维持最小权限。
3. 部署并启动 `binance-gateway`，配置仅回环监听与随机 token。
4. 部署网站，设置同一 token 与 `BINANCE_GATEWAY_BASE_URL=http://127.0.0.1:8788`。
5. 先检测网关、公共行情和只读账户；确认无误后才考虑任何交易权限。
