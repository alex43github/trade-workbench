# TradingView 风格指标显隐设计

## 背景

当前交易图表使用 TradingView Lightweight Charts 绘制，已有若干内置指标，但指标管理器使用普通开关样式，不能像 TradingView 一样通过每个指标旁边的小眼睛独立控制显隐。用户同时希望了解能否直接接入 TradingView 社区指标。

## 结论与范围

当前图表不是 TradingView Advanced Chart，不能直接导入或执行其他用户发布的 Pine Script，也不能安全地在浏览器中执行任意社区代码。本次先实现可维护的“指标注册表 + 内置/审核通过的 TypeScript 指标 + TradingView 风格眼睛显隐”。

以后若要原生运行任意 Pine 社区指标，需要单独嵌入 TradingView Advanced Chart；它与当前自定义订单、持仓和策略叠加层不是同一渲染上下文，不纳入本次改动。

## 目标

- 每个指标都有独立的可见性状态和小眼睛按钮。
- 点击眼睛只切换图表展示，不删除指标参数、不重置指标配置、不影响交易策略和订单。
- 复用现有指标计算与 Lightweight Charts 绘制逻辑，先覆盖当前内置指标。
- 指标状态按交易品种持久化，刷新后恢复；服务端保存的参数与可见性不允许导致任意代码执行。
- 新增指标必须注册明确的 `id`、名称、说明、设置字段和渲染绑定，禁止散落在 JSX 中用字符串分支隐式接入。

## 指标注册表

注册表为每个指标提供：

- 稳定 `id`；
- 展示名称与简短说明；
- 默认可见性；
- 参数 schema 与颜色配置；
- 计算/绘制绑定；
- 可见性变更时需要更新的 series 或 overlay。

第一阶段纳入现有 MA、EMA、ATR、AVWAP、Volume Profile 和 Vegas 等指标。指标计算仍只使用服务端/页面已提供的行情数据；注册表不接受用户上传的 JavaScript 或 Pine 源码。

## 页面行为

- 指标按钮打开管理器；每个指标行左侧放置眼睛按钮。
- 可见时眼睛为开启态，不可见时为关闭态；按钮使用 `aria-label` 和 `aria-pressed`，并提供文字/状态提示以支持键盘和读屏。
- 点击指标名称或参数区域不应意外切换显隐；只有眼睛按钮切换可见性。
- 指标隐藏后保留其参数和数据缓存，再次显示时不重新创建无关的交易叠加层。
- 订单、仓位、止盈止损等非指标叠加层继续使用现有独立显隐控制。

## 持久化

扩展现有按品种保存的指标设置接口，加入各指标的 `visible/enabled` 字段。读取时对缺失字段应用默认值；写入时严格按注册表过滤字段，忽略未知指标和未知设置，避免把任意对象当作可执行配置。

## 测试与验收

- 注册表测试确认指标 id 唯一、默认值完整、未知指标不会进入绘制流程。
- 可见性测试确认每个指标只影响自己的 series/overlay，隐藏后参数仍保留。
- API 测试确认可见性可保存/恢复，并拒绝未知字段。
- 页面测试确认每个指标有眼睛按钮、`aria-pressed` 状态和可访问名称，点击后不会触发下单或订单叠加层变化。
- 手工验收：分别隐藏/显示 MA、EMA、AVWAP、成交量分布等指标，切换品种并刷新页面，确认状态和图表一致。
