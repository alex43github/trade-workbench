# 多专家 AI 交易咨询平台 MVP 设计规格

日期：2026-08-13  
状态：用户已确认；MVP v0.1 已实现，盲测与完整自动复盘按后续阶段推进
产品性质：交易研究、建议与模拟交易；MVP 不提供真实下单

## 1. 目标

在现有 `trade-workbench` 上交付一个可日常使用的纵向切片：系统读取 Binance 公开行情，组织 ICT、街哥、静心、bit浪浪四位专家完成独立分析、匿名质询与最终陈述，生成可追溯的综合建议；同时为四位专家维护独立的 500 USDT、最高 10 倍杠杆模拟账户，并保存每日分析与基础复盘。

MVP 要验证五个核心假设：

1. 四套交易 Skill 可以稳定产出同一结构的可执行建议。
2. 盲独立判断、交叉质询和最终判断能够完整存档并比较。
3. 2/4 一致规则能筛出值得 Bark 提醒的条件型机会。
4. 专家市场观点与账户实际操作可以分开评估。
5. 每日分析、模拟交易与复盘记录能形成以后接入盲回放和策略晋级的可靠数据基础。

## 2. MVP 范围

### 2.1 必须真实可用

- 首页“今日驾驶舱”，展示市场摘要、最高优先级机会、四专家状态、模拟账户摘要、最近复盘与服务健康度。
- BTC、ETH、SOL、HYPE 四个核心资产；配置结构允许扩展至八个。
- Binance 公开日线、4H、1H K 线读取、收盘状态检查和数据快照哈希。
- 四专家结构化会诊：R1 独立分析、R2 匿名质询、R3 最终意见、R4 规则仲裁。
- 统一 Decision Contract、2/4 共识逻辑及意见归档。
- Bark 每日摘要和机会状态变化通知，包含去重和失败重试记录。
- 每位专家独立正式模拟账户：初始 500 USDT、逐仓、1～10 倍杠杆、不自动续资。
- 市场意见与账户决定分别保存；账户没有余额也继续发表意见。
- 基础复盘中心：昨日计划、已完成模拟交易、每日复盘列表及详情。
- 分析、订单、成交、复盘、专家版本和行情快照之间可追溯。
- 没有 OpenAI Key、Skill 运行器或 Bark Key 时明确降级，不生成冒充真实专家的内容。

### 2.2 只预留接口，MVP 不实现

- 任意时间点历史盲测房间与真实日期加密映射。
- NautilusTrader 高保真事件撮合、逐笔/订单簿撮合和历史资金费率回放。
- 十天探索期的无限实验重启机制。
- 自动提出候选经验、Champion–Challenger、样本外晋级和策略版本树完整工作流。
- R1 基线影子账户和委员会影子账户的真实自动执行。
- 全市场动态强势币筛选自动加入四个扩展槽位。
- 周复盘、月复盘的完整自动归因。
- Hummingbot、Binance 私有交易接口或任何真实下单。

上述项目保留稳定领域接口，第二阶段不需要重写 MVP 数据。

## 3. 已确认的产品规则

### 3.1 专家身份

- ICT：流动性目标、高低周期叙事、FVG/OB 与时间窗口。
- 街哥：裸 K 结构、箱体、真假突破、回踩及 AVWAP/FRVP。
- 静心：位置学、右侧确认、多周期一致性与风险纪律。
- bit浪浪：市场季节、分歧级别、强势币、二次启动与高位风险。
- 四位专家权重平等；bit浪浪承担强势币观察职责但没有额外票权。
- 原始 Skill 永久只读；MVP 保存 `skill_version`，不自动修改 Skill。

### 3.2 会诊流程

1. R0：检查行情完整性、计划字段和风险几何。
2. R1：四位专家在看不到其他意见、持仓与盈亏的条件下独立分析。
3. R2：系统匿名展示论点与反证，专家逐条回应。
4. R3：每位专家提交最终意见，可维持或修改 R1。
5. R4：纯规则仲裁器汇总投票；不能创造第五个交易观点。

R1、R2、R3 均永久保留。一次运行中某位专家失败时最多自动重试两次；仍失败则标记失败。至少三份有效 R3 才能生成可推送机会，否则只保存“不完整会诊”。

### 3.3 共识规则

- 4/4 同向：强一致。
- 3/4 同向：中强一致。
- 2/4 同向且其余观望：条件型机会，可推送。
- 2/4 同向、一个观望、一个反对：可推送，必须突出反方风险。
- 2 多对 2 空：只生成分歧提醒，不作为交易机会。
- 少于两位同向：归档，不发机会通知。
- 信心不做简单平均；MVP 展示各专家的 `P(trigger)`、`P(win | trigger)` 和证据完整度。

### 3.4 自动运行

- 每日自动分析目标时间为 Binance UTC 日线收盘后的北京时间约 08:05。
- 实际定时触发由 Cloudflare Cron 或受保护的任务端点完成，且用 `analysis_date + snapshot_hash` 保证幂等。
- 首先复盘昨日计划，再冻结当日行情快照，再执行新会诊。
- AI 只看已收盘日线、4H 和 1H；未收盘 K 线不进入决策输入。
- 盘中不持续调用 AI。MVP 仅保存专家声明的触发、失效、有效期与复查条件；轮询器检测状态变化。

## 4. 信息架构

主导航：

1. 今日驾驶舱 `/`
2. 专家会诊 `/consultations`
3. 模拟竞赛 `/arena`
4. 复盘与进化 `/reviews`
5. 盲测实验室 `/replay`（MVP 为明确标记的下一阶段说明页）
6. 市场雷达 `/radar`（保留现有能力）
7. 连接设置 `/settings`

### 4.1 今日驾驶舱

- 当前数据日期、快照质量和最后成功运行时间。
- 四个核心资产的共识卡片，按强一致、条件机会、分歧、观望排序。
- 当日最高优先级计划：触发区、失效、目标、有效期、支持/反对专家。
- 四位专家账户权益、持仓数量、当日盈亏和风险状态。
- 最近一条复盘发现，但不把未批准经验注入正式分析。
- Bark、行情、AI 和任务运行状态。

### 4.2 会诊详情

- 左侧为 K 线及关键计划价位。
- 中间为 R1、R2、R3 时间线。
- 右侧为 R4 综合卡片、核心共识与最强反证。
- 每位专家卡片同时显示市场意见和账户决定。
- 所有数据标明真实、降级、演示或缺失状态。

### 4.3 模拟竞赛

- 四位专家账户并排展示，不合并资金。
- 默认展示收益、最大回撤、总费用、风险暴露、交易次数和纪律状态，不在 MVP 合成单一总分。
- 查看账户可进入持仓、活动计划、订单、成交和资金曲线。
- MVP 不允许用户替专家下单；账户行为只能来自已保存的专家账户决定或测试夹具。

### 4.4 复盘中心

- 待复盘、已完成、证据不足三个列表。
- 详情同时展示原始判断、原始行情快照、执行结果、后续走势和归因。
- 分别评价判断质量、执行质量和结果质量。
- MVP 可生成候选经验草稿，但其状态固定为 `draft`，不会改变任何正式决策。

## 5. 领域模型

### 5.1 Decision Contract

每份专家意见必须包含：

- `consultation_id`、`expert_id`、`round`、`skill_version`、`snapshot_hash`
- `symbol`、`market_regime`、`direction`、`setup_name`
- `context_timeframe`、`execution_timeframe`、`valid_until`
- `trigger_conditions[]`、`entry_zone`
- `invalidation`、`targets[]`、`management_plan`
- `leverage`、`margin_usdt`、`max_loss_usdt`、`expected_rr`
- `trigger_probability`、`win_probability_given_trigger`、`evidence_completeness`
- `supporting_evidence[]`、`refuting_evidence[]`、`unknowns[]`
- `no_trade_reasons[]`、`source_refs[]`

方向枚举：`LONG`、`SHORT`、`NEUTRAL`。只有 LONG/SHORT 且 R0 合法的意见才能成为交易计划。

### 5.2 主要数据表

- `experts`：专家身份、显示信息、Skill 标识与启用状态。
- `strategy_versions`：专家当前正式 Overlay；MVP 只创建初始只读版本。
- `market_snapshots`：币种、周期、最后收盘时间、来源、质量、哈希和压缩行情 JSON。
- `consultations`：分析日期、币种、状态、快照及运行版本。
- `expert_opinions`：R1/R2/R3 结构化结果和原始模型响应摘要。
- `consensus_decisions`：R4 结果、支持/反对数量、通知状态与状态版本。
- `expert_accounts`：专家、赛季、初始余额、现金、权益、费用、账户状态。
- `expert_positions`、`expert_orders`、`expert_trades`、`expert_equity_snapshots`。
- `review_tasks`、`review_reports`：复盘类型、三维评分、归因和候选经验草稿。
- `notification_deliveries`：Bark 请求、去重键、结果、错误和重试次数。
- `job_runs`：每日分析各阶段状态、开始结束时间和失败原因。

新表与旧 `paper_*` 表并存。MVP 页面切换到新专家账户；旧终端保留为 legacy 工具，避免破坏用户现有数据。

## 6. 服务边界

### 6.1 Market Data Gateway

负责 Binance 公开行情获取、仅保留已收盘 K 线、重试、降级标记、快照哈希与缓存。AI 和模拟账户不直接访问 Binance。

### 6.2 Expert Runner

定义统一接口：输入专家身份、Skill 版本、市场快照和会诊轮次，输出 Decision Contract。MVP 优先支持服务器端配置的 OpenAI Responses API；没有可用专家运行器时，返回 `unavailable`，不使用规则模板伪装专家。

本地 Skill 文件不应由 Cloudflare Worker 运行时直接读取。部署前将每位专家所需的精简、版本化系统指令构建为服务器端资源；原始知识库仍保留来源引用和只读版本。

### 6.3 Consultation Orchestrator

组织 R0～R4、控制盲独立输入、匿名化 R2、重试与幂等。它不包含专家交易知识，也不直接修改账户。

### 6.4 Consensus Engine

纯函数实现投票规则、合法性检查和 Bark 是否允许推送。所有结果可通过固定输入复现。

### 6.5 Paper Portfolio Service

按 `expert_account_id` 管理账户。MVP 使用 Binance 公开标记价格或已收盘 1 分钟数据进行保守模拟，支持市价开仓、固定止损/止盈、关闭仓位、手续费、逐仓和 1～10 倍杠杆。明确标记尚未实现完整订单簿、历史资金费率与真实强平阶梯。

### 6.6 Review Service

按昨日计划和已完成交易创建复盘任务，冻结复盘输入，生成三维评价及归因。MVP 只保存候选经验草稿，不自动晋级。

### 6.7 Notification Service

通过服务端 `BARK_BASE_URL` 或 `BARK_DEVICE_KEY` 发送，浏览器永远不接触密钥。使用 `plan_id + state_version + channel` 去重；网络失败记录后指数退避，最多三次。

## 7. 数据流

每日任务：

1. 创建幂等 `job_run`。
2. 检查四个核心资产数据是否完整。
3. 对昨日计划生成或补齐复盘任务。
4. 为每个币种冻结 D/4H/1H 快照与哈希。
5. 并发执行四位专家 R1；各专家看不到其他意见。
6. R0 筛出有效结果；对候选机会执行匿名 R2。
7. 执行 R3，保存最终意见和独立账户决定。
8. R4 规则仲裁，更新机会状态版本。
9. Paper Portfolio Service 验证账户决定；不合法决定被拒绝并记录，不影响公开观点。
10. 生成每日摘要和符合条件的 Bark 通知。
11. 关闭 `job_run`，首页读取最终快照。

## 8. 安全与故障处理

- 不存在真实下单路由；API 响应明确返回 `real_order_route_enabled: false`。
- Binance 私钥不是 MVP 必需项，公开行情无需用户密钥。
- OpenAI、Bark 等密钥仅进入服务端环境变量，不写 D1、不返回浏览器。
- AI 输出先做 JSON Schema 校验，再做 R0 风险校验；文本不能绕过数值规则。
- 行情为演示数据时禁止生成 Bark 交易机会，也禁止自动写入专家正式账户。
- 快照不完整或过期时冻结该币种。
- 模型失败不补写虚假意见；界面显示失败专家及降级原因。
- Paper Service 故障时停止撮合，不能使用之后行情追溯补成交。
- 所有有状态写入携带幂等键，重复 Cron 不重复分析、下单或通知。
- 日志保存错误类别和匿名运行标识，不保存密钥或完整敏感 Prompt。

## 9. 技术选择

- 前端与 BFF：现有 Next.js 16、React 19、TypeScript、vinext/Cloudflare Workers。
- 图表：TradingView Lightweight Charts 5.2。
- 业务数据库：现有 Cloudflare D1 + Drizzle；K 线快照 MVP 用压缩 JSON，历史盲测阶段迁移至 Parquet/R2。
- 定时任务：Cloudflare Cron Trigger 调用每日分析服务。
- AI：OpenAI Responses API 的严格结构化输出；模型通过环境变量配置。
- 通知：Bark HTTP API。
- 第二阶段回放：独立 Python 服务包装 NautilusTrader；Jesse 用作轻量复算器。
- 未来执行：稳定 Decision API 对接用户自动交易网站或 Hummingbot，仍经过独立风控与授权。

## 10. 测试策略

### 10.1 单元测试

- Decision Contract 解析与非法字段拒绝。
- 4/4、3/4、2/4、2v2 和不足三位有效意见的全部仲裁分支。
- 未收盘 K 线过滤、快照哈希稳定性。
- 500 USDT、逐仓、最高 10 倍、费用和余额校验。
- 市场观点不因余额不足丢失；账户决定可独立拒绝。
- Bark 去重与重试状态机。
- 每日任务幂等。

### 10.2 集成测试

- 使用固定行情夹具和四专家固定响应完成 R0～R4。
- 一个专家失败时生成三专家降级会诊；两个专家失败时不推送。
- 演示行情不推送、不进入正式账户。
- 专家账户开仓、止损、止盈和交易后复盘链路。
- D1 迁移不会删除旧 `paper_*` 和 `trade_knowledge` 数据。

### 10.3 页面验收

- 桌面和手机均能查看今日驾驶舱、会诊、竞赛和复盘。
- 页面清楚显示数据来源、更新时间、专家失败和降级状态。
- 首页可以在三次点击内进入任一专家意见的原始证据。
- 设置页不出现浏览器端密钥输入，不泄露环境变量。

## 11. MVP 验收标准

满足以下条件才算第一版完成：

1. 四个核心资产可从真实 Binance 公开数据形成已收盘 D/4H/1H 快照。
2. 使用固定专家夹具时，完整会诊可重复运行并保存 R1/R2/R3/R4。
3. 配置真实 AI 后，四位专家均输出通过 Schema 的独立意见；失败时正确降级。
4. 2/4 及以上机会按规则生成 Bark，重复运行不重复发送。
5. 四个 500 USDT 专家账户彼此隔离，最高杠杆无法超过 10 倍。
6. 分析记录、账户决定、订单、成交和复盘可以从 UI 相互跳转。
7. 没有任何真实订单接口，演示数据不能产生正式交易或机会通知。
8. `npm test`、`npm run lint` 和新增领域测试通过。

## 12. 后续阶段

MVP 稳定后依次交付：

1. Blind Replay Coordinator 与任意时间点、隐藏日期/币种的盲测房间。
2. NautilusTrader 高保真撮合和 Jesse 交叉验证。
3. 十日探索期、正式盲测排行和实时赛季。
4. 候选经验、对照实验、样本外、影子账户与人工晋级。
5. 动态强势币池、周/月复盘和委员会效果校准。
6. 只读 Decision API；最后才考虑带人工授权的外部自动交易适配。

## 13. 明确不保证的事项

- 专家信心不是客观真实胜率，必须经过长期校准。
- 历史或模拟盈利不能证明未来盈利。
- MVP 撮合不是交易所级成交仿真。
- AI 的“学习”是受治理的版本化经验晋级，不是模型权重在线自我训练。
- 本产品第一阶段只提供研究、建议和模拟交易，不构成自动下单系统。
