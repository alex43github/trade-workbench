# 雷达二阶段精筛与评分设计规格

> 状态：已获用户确认，待实现。

## 目标

为市场雷达顶部的全部栏目统一增加“粗筛 → 精筛 → 评分排序”流程。每个栏目先保留自己的原始筛选规则，再仅针对当前栏目的候选集合使用 15m、1h、4h 已收盘 K 线条件进行组合精筛，并根据趋势、Vegas、量能、OI、波动率和数据质量排序。

## 交互规则

- 图 2 的综合榜、全部雷达、逼空重点、候选、筹码集中、风险检查、MA30 × OI 增仓、破底翻、Vegas 强势九个栏目都显示同一组精筛控件。
- 精筛控件包含六个独立条件按钮：多头站上 15m/1h/4h MA30，以及空头低于 15m/1h/4h MA30。
- `AND` 和 `OR` 为互斥模式按钮，默认 `AND`。
- 未选择条件时不生成精筛结果，只显示当前栏目的粗筛结果。
- 选择一个条件时，`AND` 与 `OR` 结果相同。
- `AND` 要求同一候选满足所有已选条件；`OR` 要求满足任一已选条件。
- 选中的条件可以跨方向组合；例如“4h 站上 + AND + 15m 低于”表示同一币必须同时满足两个跨周期条件，结果标记为混合方向证据。
- 精筛输入必须是当前栏目完整的粗筛集合。搜索框只影响展示，不缩小扫描输入；切换栏目或候选集合变化后，旧精筛快照必须标记为不匹配并要求重新筛选。

## 数据规则

- MA30 条件只使用 Binance Futures 最新一根完整收盘 K 线，严格比较 `close > MA30` 或 `close < MA30`。
- 趋势持续性使用最近已收盘 K 线的连续站上/低于统计；未达到历史长度、请求失败或非有限数据不算命中。
- Vegas 多头严格使用 `MA30 > EMA144 > EMA169 > EMA576 > EMA676`，空头使用严格反向；长期数据不足时沿用短期通道回退，但完整通道评分高于短期回退。
- 量能和 OI 使用同周期历史基准，比较最近短期值与过去 7 天、30 天滚动基准；波动率使用 ATR/已实现波动率与相同基准比较。
- 量能、OI 和波动率属于评分证据，不替代用户选择的 MA30 硬条件。
- 缺失数据按 0 分并显示数据缺口，不能默认满足条件。现有风险否决和交易安全闸门不受评分影响。
- 有效 Binance USDT 永续候选超过 100 个时，先完成所有候选的基础条件判断，再优先对强势预评分靠前者读取深度历史数据；任务按批次继续处理，不静默丢弃候选。

## 评分

精筛通过后生成 0–100 分：

| 证据 | 权重 |
| --- | ---: |
| 均线方向与收盘持续性 | 25 |
| Vegas 排列与通道发散 | 25 |
| OI 扩张及方向配合 | 20 |
| 短期量能扩张 | 15 |
| 波动率放大 | 10 |
| 数据完整性与流动性 | 5 |

各项按证据强度累加；同一类别跨周期采用递减加分，避免重复计权。精筛结果显示总分、命中的条件、各项分项分数和数据完整度，并按总分降序排列；同分时按命中条件数、流动性和币种字典序稳定排序。

## API 与存储

- 扩展现有受保护的 `/api/radar/multitimeframe` 手动扫描请求，接受 `{ symbols, conditions, mode }`，保留旧请求兼容性。
- 快照保存当前窗口符号集合、条件组合、AND/OR 模式、基础多周期指标、历史评分证据和排序后的精筛结果。
- GET 只读最近快照；POST 继续使用 operator guard、进度状态和单任务互斥，不连接任何下单接口。
- 现有定时器仍只生成基础 MA30/Vegas 快照；用户点击“立即筛选”才运行当前窗口的组合精筛和深度评分。

## 页面验收

- 九个栏目均能选择六个条件和 AND/OR，并显示当前窗口候选数量、扫描状态、数据缺口和重新筛选提示。
- AND 显示交集，OR 显示并集；每个币展示方向、匹配条件、分项证据和总分。
- 粗筛结果和精筛结果分区展示；精筛结果为空时显示明确原因。
- 结果只提供研究排序，不改变实盘、保护策略或任何交易执行路径。
