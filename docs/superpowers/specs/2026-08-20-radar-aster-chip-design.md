# 雷达 Aster OI 与链上 Top10 筹码设计

## 目标

把雷达表格中的 Aster 与链上筹码字段从静态待接入状态推进到可控的参考指标：Aster 使用公开 OI，链上只展示排除交易所和协议地址后的 Top10 持仓集中度，主要服务低市值小币种观察，不直接升级为交易信号。

## 数据与安全边界

- Aster 通过服务端公开 Futures API `https://fapi.asterdex.com/fapi/v1/openInterest?symbol=...` 获取当前 OI；不使用浏览器爬取，不使用账户密钥。
- 先读取 Aster OI 快照并与上一次快照比较，`asterOi1h` 表示约 1 小时变化百分比；没有上一快照时显示待接入。
- 链上数据通过服务端 Bitquery GraphQL 适配器获取 Top holders；凭证只存在服务端环境变量。
- 地址过滤由显式配置的地址标签/地址集合完成，至少排除交易所、LP/池、桥、销毁地址和项目金库；过滤后没有足够有效持仓时返回数据不足。
- Top10 百分比定义为过滤后有效持仓 Top10 余额之和 / 过滤后有效持仓总余额，不把它描述为真实控盘结论。
- API 失败、限流、Token 地址缺失或链不支持时返回 `null` 与 `pending`，不使用演示数字参与评分。

## 实现边界

- 新增 Aster OI 服务、链上 Top10 服务、地址标签配置和一个雷达聚合层。
- 雷达 API 在现有 Binance/演示数据基础上补充两个字段，并保留现有 `coverage` 状态。
- 表格显示 `Aster OI` 和 `链上 Top10`；移除“大户增量”占位文案，改成 OI 变化参考。
- 小币种只作为研究参考，UI 增加数据源时间和“非交易信号”提示。
- 使用内存/数据库快照缓存，避免刷新页面时重复请求和触发来源方限流。

## 验收标准

- 有 Aster OI 时能显示当前 OI 变化；无数据时显示“待接入”，不显示模拟值。
- 有链上持仓数据时显示过滤后的 Top10%；交易所/LP/桥/销毁/金库地址不计入分母和 Top10。
- 地址、API Token 和原始响应不泄露到浏览器或日志。
- 单元测试覆盖 OI 变化、地址过滤、Top10 计算、空数据和限流失败；完整构建和测试通过。
