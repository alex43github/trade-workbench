# 自选币来源与强势生命周期管理

## 目标

将自选币由单一添加来源改为可并存的来源集合，并以稳定优先级渲染。系统只自动移除由 1 小时 MA30 ±3 ATR 强势扫描加入的来源，绝不删除用户手动加入的自选。

## 固定排序

自选列表按以下分组顺序返回，同组保持最初加入顺序：

1. 固定核心：`BTCUSDT`、`ETHUSDT`、`SOLUSDT`、`HYPEUSDT`、`ENAUSDT`。五项永远存在且不可由自动任务移除。
2. 当前 Binance USD-M 非零持仓。
3. 用户手动加入的币。
4. 1 小时超强势币，按连续位于阈值外的已收盘 K 线数量降序，再按币种排序。

若一个币具备多种来源，只显示一次，并采用最高优先级分组。

## 来源模型与迁移

保留 `watchlist_entries` 作为币种展示信息，新增一张一币多来源的关联表。来源限定为：

- `PINNED`：五个固定核心币。
- `POSITION`：当前真实持仓。
- `MANUAL`：用户星标或历史自选迁移。
- `ATR_STRONG_1H`：1 小时超强势扫描。

既有 `MANUAL` 行迁移为 `MANUAL` 来源；既有 `ATR_BAND` 行迁移为 `ATR_STRONG_1H`。条目只要仍有至少一个来源便保持可见；无来源时将其逻辑删除。新增/删除来源必须是幂等操作，扫描重复运行不得重复条目或改写手动来源。

## 持仓同步

服务器每次维护任务运行时读取 Binance 的真实非零持仓并同步 `POSITION` 来源。账户查询接口也复用相同同步函数，以缩短已打开网页时的变化延迟。仓位归零时仅撤销 `POSITION` 来源；若仍有 `MANUAL`、`PINNED` 或 `ATR_STRONG_1H` 来源，币继续保留。

## 1 小时超强势同步

每个整点、在 1 小时 K 线确认收盘后，由现有 ATR 生命周期扫描更新来源：

- 初次加入：同方向连续至少 3 根已收盘 1 小时 K 线收盘在 `MA30 + 3×ATR(14)` 上方（多头）或 `MA30 - 3×ATR(14)` 下方（空头）。
- 继续保留：最新已收盘 1 小时 K 线仍在同侧 `±3ATR` 阈值之外。
- 立即撤销：最新已收盘 K 线回到或穿过阈值内侧；多头 `close <= MA30 + 3×ATR`，空头 `close >= MA30 - 3×ATR`。不等待进入 `HISTORY`。
- 扫描不完整、降级或数据读取失败时不撤销已有 `ATR_STRONG_1H` 来源，避免因临时 Binance 数据异常误删。

15 分钟和 4 小时扫描不影响 `ATR_STRONG_1H` 来源。

## API 与前端

`GET /api/watchlist` 返回按优先级排序后的去重列表，并可返回非敏感来源摘要供界面调试。星标加入创建 `MANUAL` 来源；星标移除仅撤销 `MANUAL` 来源。固定币的星标移除不影响固定展示；其它自动来源仍存在时条目保持显示。

交易页继续复用 `useWatchlist`，无需把排序或强势判定复制到浏览器。页面刷新后由服务端投影恢复同一顺序。

## 安全与边界

所有持仓读取保持只读；本功能不下单、不调整 Binance 持仓、不开放新的公开端口。维护任务只能使用现有内部令牌。币安账户或行情读取失败时保守保留已有自动来源，并记录可诊断错误。

## 验收与测试

- 固定五币即使没有其他来源也始终位于前五，顺序固定。
- 非零持仓紧随固定五币；平仓仅移除 `POSITION` 来源。
- 手动自选不因超强势回撤、扫描失败或平仓而自动删除。
- 连续三根阈值外的 1 小时币加入；下一根回到阈值内便撤销其 `ATR_STRONG_1H` 来源。
- 具有手动和强势双来源的币在撤销强势来源后仍保留。
- ATR 扫描降级时不执行自动删除。
- 相关纯函数、数据库投影、维护路由和前端 hook 均有回归测试；部署后检查服务、维护定时器与交易页。
