# 强势币结构雷达与四专家 Bark 预警设计规格

日期：2026-08-13  
状态：待用户书面审阅  
依赖规格：`2026-08-13-ai-trading-advisory-mvp-design.md`  
产品性质：形态发现、研究建议、持仓只读与人工决策辅助；不自动下单

## 1. 目标

在现有 `trade-workbench` 上增加一个面向 Binance U 本位永续合约的强势币雷达，持续发现两类多头候选：

1. 长期整理平台下方出现假跌破，价格快速收回并重新站上平台；
2. 价格以实体和量能突破自动识别的长期下降趋势线。

系统扫描全部状态为 `TRADING` 的 USDT 本位永续合约，同时维护 15m、1h、4h 三个周期，1h 为主预警周期。形态命中后，系统组织 ICT、街哥、静心、bit浪浪四位专家完成独立分析、匿名质询和最终陈述，并通过 Bark 推送候选、确认、加仓候选、止盈观察和失效状态。

TradingView 免费版只挂载一个合并式 Pine Script 指标，用于收到 Bark 后的图形复核。全市场扫描、四专家会诊、Binance 持仓只读和 Bark 均由本地服务完成，不消耗 TradingView Alert 配额。

## 2. 已确认的产品规则

- 扫描市场：Binance USDⓈ-M Futures，全部 `quoteAsset=USDT`、`contractType=PERPETUAL`、`status=TRADING` 的合约。
- 扫描周期：15m、1h、4h；1h 为主预警，15m 用于更早发现和执行复核，4h 用于结构背景。
- 趋势线由系统自动识别，不依赖用户在 TradingView 手动画线。
- Bark 同时推送“候选”和“确认”；强势币可能不回踩，因此候选不可省略。
- Bark 可附研究型限价区、结构止损、两级目标、有效期、反方意见和 TradingView 入口。
- Binance 私有接口只读取账户、持仓和活动委托；不下单、不撤单、不修改杠杆或保证金模式。
- 同一币种、周期和结构只在状态升级或失效时再次推送，避免重复轰炸。
- 四位专家投票等权；bit浪浪在强势币场景担任“执行主专家”，但不获得额外票数。
- 不允许亏损摊平式加仓。只有价格继续证明原方向正确并形成新结构确认，才能产生加仓候选。
- 所有专家结论属于 `research_only / candidate_unverified`；历史案例、视频画面、口述概率和模拟结果都不等于已验证优势。

## 3. 范围

### 3.1 第一版必须实现

- Binance 合约清单同步、历史 K 线启动缓存和实时 1m K 线流。
- 本地把已收盘 1m K 线聚合为 15m、1h、4h，只对已收盘 K 线做判定。
- “平台假跌破后收回”和“下降趋势线放量突破”两个无前视检测器。
- 候选、确认、加仓候选、止盈观察、失效五状态生命周期。
- 形态评分、流动性背景、数据质量门控和结构去重。
- 四专家 R1/R2/R3 会诊和纯规则 R4 仲裁。
- bit浪浪强势币执行主案、市场季节与高位禁做检查。
- Binance 当前持仓只读和信号后持仓状态追踪。
- Bark 推送、去重、失败重试和本地通知日志。
- `Strong Coin Structure Radar` 单一 Pine Script 指标。
- 本地雷达列表和详情页，展示形态几何、专家意见、持仓状态和通知历史。
- 固定历史夹具回放和前向观察记录；不得在没有统计结果前显示胜率承诺。

### 3.2 第一版不实现

- 真实订单、自动限价单、自动止损、自动加仓或自动减仓。
- 根据账户权益自动计算真实下单数量或杠杆。
- 用模型文本绕过数值风控或交易所规则。
- 把 TradingView 手动画线读入 Pine 或本地扫描器。
- 在 TradingView 内扫描全部币种或依赖付费 Alert。
- 根据单张历史截图反推固定参数或宣称形态必然拉升。
- 在线自动修改四个原始 Skill。

## 4. 行情与扫描架构

### 4.1 行情来源

- 结构和量能：Binance U 本位永续合约成交 K 线。
- 数据质量复核：标记价格和指数价格，仅用于发现异常长针、基差或报价问题，不替代成交 K 线结构。
- 市场环境：BTCUSDT、ETHUSDT、TOTAL 替代字段不可凭空构造；第一版使用 BTC/ETH 同周期方向、全市场涨跌分布、24h 成交额和公开 OI/资金费率等可取得字段。
- 私有账户：只读 `account-information`、`position-information` 和当前委托状态；密钥永不返回浏览器。

### 4.2 实时数据流

1. 启动时拉取 `exchangeInfo`，建立当前合约池。
2. 每个合约订阅一条 1m K 线流；总流按 Binance 单连接限制拆分到多个连接。
3. 只在 1m K 线 `closed=true` 时写入缓存，并本地聚合 15m、1h、4h。
4. 各周期聚合 K 线收盘后触发扫描；未收盘 K 线只用于页面预览，不进入信号。
5. 启动或断线恢复时使用 REST 分批补齐各周期历史数据，限制并发和请求权重；已有本地缓存时只补缺口。
6. 同一 `symbol + timeframe + close_time` 使用幂等键，重连和重复消息不得重复扫描。

### 4.3 数据质量门控

以下任一情况禁止生成专家点位和 Bark 交易计划，只记录数据告警：

- 当前周期缺 K、时间戳乱序或最后收盘时间过期；
- 交易所状态不是 `TRADING`；
- 结构依赖的历史长度不足；
- 成交 K 线与标记/指数价格存在无法解释的异常差异；
- 价格步长、数量步长或符号元数据缺失；
- 本地时钟与 Binance 服务器时间偏差超过 5 秒且无法自动校正。

## 5. 形态一：长期平台假跌破后快速收回

### 5.1 平台候选

检测器只使用触发 K 线之前已经收盘的数据。第一版同时搜索 48、96、168 根 K 线窗口，并选择评分最高且不与更高质量平台冲突的结构。

一个平台候选必须满足：

- 上沿和下沿分别至少出现 3 次相互分离的触达；相邻触达至少间隔 3 根 K 线；
- 边界使用局部高低点的稳健中位区间，不由单根极端影线决定；
- 边界容差默认取 `max(0.25 × ATR(14), 0.30% × price)`；
- 平台宽度、边界斜率和区间内收盘占比共同进入质量评分；
- 48/96/168 和上述容差是第一版研究参数，必须通过历史回放和前向样本做敏感性测试，不能被描述为街哥或其他专家的固定参数。

### 5.2 候选触发

满足下列条件后生成 `RECLAIM_CANDIDATE`：

- 价格低点有效扫过平台下沿；
- 同一根或之后最多 3 根已收盘 K 线重新收在平台下沿上方；
- 收回不是单纯影线，收盘实体重新进入平台；
- 能定义明确失效点：扫低极值或重新跌回平台下方后的结构低点；
- 数据质量门控通过。

该定义遵守“假跌破不是单根插针，而是扫过、收回、重测和失效的过程”原则。来源要求至少保留 `JG-002 @ 00:08:21-00:10:13`、`JG-040 @ 00:14:46-00:15:27`，以及静心“影线穿区域而实体收回”和右侧确认来源 `JX-034 @ 00:43:32-00:47:14`。

### 5.3 确认触发

候选后的未来 6 根当前周期 K 线内，满足任一条件升级为 `RECLAIM_CONFIRMED`：

- 回踩平台下沿容差区，低点未破候选失效点，收盘重新离开边界；
- 形成小周期更高低点并突破收回后的局部高点；
- 没有回踩，但价格以至少 0.75 ATR 的实体位移快速离开平台下沿，同时量能继续扩张。

若候选后收盘再次跌破平台下沿并破坏结构，状态变为 `INVALIDATED`。

## 6. 形态二：下降趋势线放量突破

### 6.1 自动趋势线

- 局部高点只能在右侧 3 根 K 线收盘后确认为 pivot，确认前不得用于连线。
- 在 48、96、168 根窗口内寻找依次降低的已确认 pivot high。
- 一条候选下降线至少有两个锚点和一个额外触达验证；触达容差使用 `max(0.20 × ATR(14), 0.25% × price)`。
- 斜率必须为负，锚点之间至少间隔 5 根 K 线；当前触发前不能已有持续站在线上方的收盘区间。
- 同一时间存在多条线时，优先选择触达更多、跨度更长、残差更小且最近仍有效的趋势线。
- 自动线的锚点、确认时间和算法版本全部保存，避免事后重画。

### 6.2 候选触发

满足下列条件后生成 `TRENDLINE_BREAKOUT_CANDIDATE`：

- 当前已收盘 K 线的实体收在线上方，不能只由上影线穿越；
- 收盘超过趋势线的距离大于容差；
- 当前成交量至少为前 20 根成交量中位数的 1.5 倍；
- K 线实体和相对 ATR 位移进入评分，极端长上影或收盘靠近最低点会降级；
- 上方存在可定义的下一处结构目标，而不是直接撞入近端高周期压力。

成交量倍数、pivot 宽度和容差均为待验证工程参数，不归属于四个专家的固定规则。

### 6.3 确认触发

候选后的未来 6 根当前周期 K 线内，满足任一条件升级为 `TRENDLINE_BREAKOUT_CONFIRMED`：

- 回踩原下降线或突破 K 实体上部区域，收盘保持在线上；
- 形成更高低点并突破候选 K 高点；
- 没有回踩但继续快速离开，累计位移达到 1 ATR 且没有收回趋势线下方。

候选或确认后若收盘重新回到趋势线下方并破坏局部高低点结构，状态变为 `INVALIDATED`。

强突破的研究依据必须保留街哥“快速离开、浅回踩、重新收回则降级”的来源：`JG-002 @ 00:01:37-00:02:58`、`JG-015 @ 00:02:57-00:03:23`。它是候选模型，不是必涨承诺。

## 7. 信号状态机

```text
WATCHING
  └─ 已收盘形态成立 → CANDIDATE
       ├─ 回踩/延续确认 → CONFIRMED
       │    ├─ 新结构确认且持仓同向 → ADD_CANDIDATE
       │    ├─ 到达目标/高位风险 → TAKE_PROFIT_WATCH
       │    └─ 结构破坏 → INVALIDATED
       ├─ 直接结构破坏 → INVALIDATED
       └─ 超过有效期 → EXPIRED
```

- 每个状态都有 `state_version`；只有状态变化、计划价格发生结构性变化或专家共识等级变化时才允许再次 Bark。
- 同一平台或趋势线的轻微数值漂移不创建新信号。
- 结构去重键包含 `symbol + timeframe + setup_type + anchor_hash`。
- 候选和确认默认有效期均为未来 6 根当前周期 K 线；专家可以缩短，不可静默延长。

## 8. 四专家会诊

### 8.1 专家职责

- 街哥：裸 K、平台、真假突破、快速离开、回踩质量和结构失效。
- ICT：高低周期叙事、流动性扫荡、FVG/OB/IFVG、折溢价和目标流动性；美股/外汇时段参数不得迁移 Binance。至少保留 `PDF-001 p.6-p.7`、`PDF-005 p.1-p.4`、`PDF-039 p.8/p.12` 等实际使用来源。
- 静心：大周期方向、小周期右侧确认、顶底转换、横盘破位后回踩和以损定量纪律。至少保留 `JX-001 @ 00:07:01-00:09:40`、`JX-011 @ 00:44:44-00:45:32`、`JX-029 @ 00:02:28-00:02:41` 等实际使用来源。
- bit浪浪：市场春夏秋冬、分歧级别、龙头/共振币、启动位置、追高风险、试单、确认加仓和分批退出。至少保留 `BL-001 @ 00:24:36-00:27:11`、`BL-012 @ 00:16:43-00:21:02`、`BL-018 @ 00:08:38-00:17:39`、`BL-019 @ 00:03:09-00:04:43` 等实际使用来源。

### 8.2 Skill 版本

- 每次会诊前读取四个 Skill 的当前文件清单和内容哈希。
- `skill_version` 使用 `skill_id + SHA-256(SKILL.md + 本次实际加载 references)`。
- bit浪浪 Skill 更新后，新会诊自动使用新哈希；旧意见保留旧哈希，不覆盖、不混算。
- 当前 bit浪浪 v1.0 已完成文本提炼，但 `visualVerified=false` 且未回测；Bark 必须显示“研究版/未验证”，不能省略。

### 8.3 真实专家运行器

本地模式优先使用 Codex 非交互运行器：

- 每位专家在独立、临时、只读会话中运行；明确点名且只加载自己的 Skill。
- 市场快照、形态几何、公开衍生数据和轮次输入通过结构化 JSON 提供。
- R1 看不到其他专家、用户实际持仓、账户盈亏和历史投票。
- 输出必须通过统一 JSON Schema；自由文本不能绕过字段校验。
- 本地运行器使用 `--ephemeral --sandbox read-only --output-schema`，不启用搜索，不允许写文件或调用交易接口。
- 可选服务器模式使用 OpenAI Responses API 和版本化 Skill Bundle；两种运行器必须产生同一 Decision Contract。
- 如果真实 Skill 运行器不可用，专家状态返回 `unavailable`。不得用硬编码规则模板冒充 ICT、街哥、静心或 bit浪浪。

### 8.4 会诊轮次

1. R0：机械检查行情、形态几何、价格关系、有效期和风险字段。
2. R1：四位专家并行盲审，冻结原始意见。
3. R2：每位专家看到另外三份匿名论点和反证，回答最强支持、最危险遗漏和使自己改变判断的条件。
4. R3：四位专家提交最终方向和计划，可维持、降级、观望或反转；修改必须记录字段差异和原因。
5. R4：纯规则仲裁，汇总票数、选择执行主案和决定 Bark 类型；不得创造第五套交易理由。

每位专家单轮失败最多重试两次。至少三份有效 R3 才能生成带点位的专家 Bark；不足三份时只允许发送机械形态通知并明确“专家会诊不完整”，不得给统一入场计划。

## 9. bit浪浪作为强势币执行主专家

四票继续等权，但强势币的执行主案按以下规则选择：

1. bit浪浪 R3 为同向且计划字段合法时，Bark 的“执行主案”优先原样采用其 entry/invalidation/targets/management，不由裁判重写。
2. bit浪浪观望或反对时，仍按四票规则显示共识，但必须标记“浪浪执行未通过”；不生成加仓候选，也不把该信号标为强势币优先执行。
3. bit浪浪判断处于秋冬、补涨末端、第五浪高位、流动性差、非龙头或大饼/以太未共振时，进入醒目风险栏。
4. bit浪浪 Skill 明确只讲思路和节点、具体点位细节需自行研究（`BL-012 @ 00:28:39-00:29:35`）。因此数值入场区、止损和目标必须来自当前市场结构；Bark 只能写“按 bit浪浪阶段/节点框架组织”，不得声称具体价格由原视频直接给出。

### 9.1 入场与试单

- 只在顺大周期、市场阶段允许且介入点没有明显远离结构时给候选限价区。
- 大级别突破后优先寻找小级别拐点；允许结构仍有效时多次独立小试，但每次失败必须先止损，不能把旧亏损滚入新计划。来源：`BL-004 @ 00:14:49-00:15:26`。
- 已远离合理结构区时标记“错过，不追”；不得为了给出点位而扩大止损。

### 9.2 加仓

只有全部满足时才生成 `ADD_CANDIDATE`：

- 当前持仓方向与确认信号同向；
- 原止损或失效点仍有效；
- 价格形成新的更高低点、回踩企稳、突破新局部高点或大小周期重新共振之一；
- 新加仓后仍能定义独立结构失效，且不是为了降低亏损均价；
- 当前不属于高位第五浪、秋冬、补涨末端或低流动性禁加场景。

第一版只给“加仓触发区和新失效点”，不给实际加仓金额或杠杆。高位与低流动性加仓风险保留 `BL-002 @ 00:32:35-00:38:08`；结构止损保留 `BL-007 @ 00:06:33-00:07:31`。

### 9.3 退出

- 第一目标优先使用下一处明确压力、前高或结构目标；到达附近后推送 `TAKE_PROFIT_WATCH`。
- 第二目标用于尾仓观察，不承诺必达。
- bit浪浪主案默认表达“目标一附近分批、剩余观察目标二”，来源 `BL-011 @ 00:33:29-00:34:06`。
- 高位、第五浪或市场转入秋冬时，即使第二目标未到也允许提示收缩预期；不得把趋势计划静默改成无限持有。

## 10. 共识和统一点位

### 10.1 投票门槛

- 4/4 同向：强一致，给完整主案。
- 3/4 同向：中强一致，给完整主案并显示少数意见。
- 2 位同向、2 位观望：条件候选，可给醒目标注的激进候选区。
- 2 位同向、1 位观望、1 位反对：推送形态和反方理由，不建议预挂限价单。
- 2 多对 2 空：只发重大分歧，不给入场点。
- 少于 2 位同向：归档，不发专家交易建议。

### 10.2 点位纪律

- R4 不平均四位专家的价格，也不创造“委员会价格”。
- Bark 完整主案来自一个具名专家的未改写 Decision Contract；强势币优先 bit浪浪，同向但 bit浪浪不可用时依次使用街哥、静心、ICT 中字段完整且 R0 合法的计划。
- 其他专家的入场区只作为支持/冲突对照。若主案与多数支持专家没有重叠，降级为“点位分歧”，不建议预挂限价单。
- 任何计划必须满足 `entry > stop`（多头）、目标价格递增、至少一个目标的净预期收益为正，并能计算风险距离；否则 R0 拒绝。
- 专家口述概率不得显示为统计胜率。系统只显示“专家主观信心/证据完整度”，后续用前向结果独立校准。

## 11. Binance 持仓只读与持仓感知

### 11.1 安全边界

- 推荐使用专用只读 API Key，关闭交易和提现权限并设置 IP 白名单。
- 服务端环境只接收 `BINANCE_FUTURES_API_KEY` 和 `BINANCE_FUTURES_API_SECRET`；不写数据库、不写日志、不返回浏览器。
- 只允许 GET 类账户、持仓和活动委托查询；代码层不存在真实下单适配器。
- 私有接口失败不阻断公共行情扫描，但 Bark 标记“持仓未知”，并禁止加仓建议。

### 11.2 状态分类

系统不凭仓位大小猜测用户的主观“试仓/满仓”，只记录可证明的状态：

- `NO_POSITION`：当前符号无持仓；
- `PRE_EXISTING_POSITION`：信号出现前已经有同向持仓，来源和计划未知；
- `POST_CANDIDATE_POSITION`：候选 Bark 之后、确认之前首次检测到同向持仓；
- `POST_CONFIRM_POSITION`：确认之后首次检测到同向持仓；
- `OPPOSITE_POSITION`：当前持仓与信号方向相反；
- `POSITION_UNKNOWN`：私有接口不可用或数据过期。

R1/R2/R3 看不到持仓，避免持仓污染分析。R4 完成后由 Position-Aware Mapper 追加持仓提示：

- 无持仓：显示候选入场区；
- 候选后已有同向持仓：不重复首仓建议，只显示确认、加仓条件和原失效点；
- 预先存在持仓：显示“与本信号关联未知”，不主动建议加仓；
- 反向持仓：显示冲突，不生成同向加仓计划；
- 持仓未知：不生成加仓建议。

## 12. Bark 通知

### 12.1 通知类型

- `候选`：形态成立且会诊达到门槛；
- `确认`：回踩或延续确认；
- `加仓候选`：持仓同向且出现新的独立结构确认；
- `止盈观察`：到达目标或进入高位风险区；
- `失效`：收盘破坏结构；
- `重大分歧`：2 多对 2 空；
- `数据/专家异常`：数据不完整或不足三位专家有效。

### 12.2 Bark 内容

每条交易型通知包含：

- 币种、周期、当前收盘价、形态、候选/确认状态和触发时间；
- 平台边界或自动趋势线当前投影价、锚点跨度和算法版本；
- 量能倍数、ATR 位移、24h 成交额和数据质量；
- 四位专家方向、支持/反对/观望票数、最强反方理由；
- 执行主案专家、入场区、结构止损、目标一/二、有效期和计划 R；
- 持仓状态、现有均价（若可读）、是否允许讨论加仓；
- bit浪浪市场阶段、龙头/共振判断、高位或追价风险；
- TradingView 链接和本地会诊详情链接；
- “研究建议、未回测、不会自动下单”标记。

### 12.3 去重与重试

- 去重键：`signal_id + state_version + channel`。
- 相同结构和状态不重复推送；价格轻微变化不产生新消息。
- Bark 网络失败指数退避，最多重试 3 次；每次结果写入通知日志。
- 当同一收盘时刻命中大量币种时，按形态评分、1h 优先级、专家共识、市场阶段和流动性排序；单条发送最高优先级，其余合并为摘要，防止通知风暴。

## 13. TradingView 免费版合并指标

指标名：`Strong Coin Structure Radar`

一个 Pine Script 指标同时提供：

- 自动平台上沿/下沿和平台着色；
- 平台假跌破、收回、确认、失效标记；
- 自动下降趋势线、pivot 锚点和突破/确认/失效标记；
- 当前量能倍数和形态评分表；
- 可选 4h/1h 背景摘要；
- 可选手动输入 Bark 给出的 entry/stop/target1/target2，在图上画研究计划线。

限制：

- Pine 指标不能读取本地四专家会诊结果；计划价需要用户手动填入，或直接在本地 `trade-workbench` 图表查看自动叠加。
- 指标只分析当前打开的符号，不负责全市场扫描。
- 第一版不创建 TradingView Alert，避免依赖免费套餐预警额度。
- Pine 和本地扫描器共享同一形态算法版本与固定夹具；由于 Pine 浮点和 pivot 语义差异，允许价格容差内一致，但不得出现方向或状态不一致。

## 14. 服务边界和文件责任

建议在 `trade-workbench` 内新增以下边界，最终文件名可在实施计划中按现有代码结构细化：

- `Market Stream Service`：合约池、1m WebSocket、REST 回补和多周期聚合。
- `Structure Detector`：平台、趋势线、评分、状态机和去重，纯函数可回放。
- `Expert Runner`：本地 Codex/服务器 Responses 两种真实 Skill 运行器。
- `Consultation Orchestrator`：R0～R4、并发、匿名化、重试和幂等。
- `Position Reader`：Binance 只读持仓和状态分类。
- `Position-Aware Mapper`：在 R4 后追加首仓/持仓/加仓提示，不影响专家原始意见。
- `Notification Service`：Bark 格式、去重、摘要和重试。
- `Radar API/UI`：候选列表、详情、专家证据、形态图和通知历史。
- `Pine Artifact`：单文件合并指标及版本说明。

检测器和状态机不得依赖 React、数据库或 AI；专家运行器不得访问 Binance 私有接口；通知服务不得修改会诊或持仓。

## 15. 数据模型

在既有多专家规格的数据表基础上增加：

- `radar_symbols`：合约元数据、状态、精度和最后同步时间；
- `market_bars` 或本地分段缓存：symbol/timeframe/open_time/OHLCV/source/closed；
- `structure_anchors`：平台边界、趋势线 pivot、算法版本和 anchor_hash；
- `radar_signals`：setup、timeframe、状态、评分、触发/确认/失效时间、有效期；
- `signal_state_events`：每次状态变化及其不可变快照；
- `position_observations`：标准化只读持仓、均价、方向、采集时间和与信号关系；
- `consultations`、`expert_opinions`、`consensus_decisions`：复用既有规格并增加 `signal_id`；
- `notification_deliveries`：复用既有 Bark 日志；
- `detector_versions`、`skill_versions`：算法和专家输入版本。

K 线可使用本地压缩缓存并设置保留期；信号、专家意见、版本和通知历史长期保存，保证复盘可追溯。

## 16. 故障与降级

- Binance 公共流中断：REST 分批回补；未补齐前不判定。
- Binance 私有账户失败：继续扫描，持仓标记未知，禁止加仓建议。
- 某一专家失败：最多重试两次；至少三位有效才可产生带点位计划。
- 两位及以上专家失败：可推送机械形态，但不得用模板补写专家点位。
- bit浪浪运行失败：仍可显示其他三位共识，但无“强势币执行主案”和加仓候选。
- Bark 失败：记录并重试；UI 始终保留信号，不因通知失败丢失。
- Pine 与本地检测不一致：以本地已保存快照为通知依据，记录差异并阻止发布新 Pine 版本，直到夹具修复。
- 数据为演示/夹具：允许页面和测试，不允许发真实 Bark。

## 17. 测试策略

### 17.1 检测器单元测试

- 平台 3 次触达、边界稳健性和窗口选择；
- 单根影线不收回不得命中；
- 同根收回、3 根内收回和超时不收回；
- 回踩确认、延续确认、失效和过期；
- pivot 必须等待右侧 3 根收盘，禁止未来数据；
- 两锚点一验证、负斜率、残差排序和旧突破线排除；
- 量能倍率、ATR 位移、长上影降级；
- anchor_hash 和状态幂等。

### 17.2 会诊与共识测试

- 四位专家 R1 输入隔离；
- R2 匿名化且不泄露专家身份；
- R3 修改留下差异；
- 4/4、3/4、2+2观望、2+1反对+1观望、2v2 和不足三位有效；
- bit浪浪支持、观望、反对和失败时的执行主案差异；
- R4 不平均价格、不创造专家未提供的点位；
- Skill 文件变化生成新版本，旧意见不变化；
- 非真实 Skill 运行器不得标记为专家意见。

### 17.3 持仓与 Bark 测试

- 无持仓、预先持仓、候选后持仓、确认后持仓、反向持仓和未知；
- 持仓信息不进入 R1/R2/R3；
- 亏损无新确认时不得生成加仓候选；
- 高位/秋冬/低流动性时加仓禁用；
- Bark 状态升级、失效、去重、摘要和三次重试；
- 演示数据绝不发送真实 Bark；
- 日志和 API 不包含密钥。

### 17.4 历史与前向验证

- 使用用户提供的两张图制作正例夹具，但不把截图当胜率证据；
- 收集同周期随机负例、假突破失败、下降线假突破和低流动性异常针；
- 无前视逐根回放，统计触发数、确认率、MFE、MAE、到目标率、失效率和通知延迟；
- 参数做敏感性测试，轻微修改窗口、容差、量能阈值后结果不应立即坍塌；
- 15m、1h、4h 分层统计，禁止合并后掩盖周期差异；
- 上线后先运行至少 14 天观察模式，记录信号但不把任何结果描述为已验证实盘优势。

## 18. 验收标准

第一版只有同时满足以下条件才算完成：

1. 全部 Binance USDT 永续可被纳入合约池，15m/1h/4h 已收盘 K 线持续更新。
2. 两类形态在固定正负夹具上无前视、可重复并产生正确状态生命周期。
3. 同一结构不会因重连或重复扫描产生重复 Bark。
4. 真实 Skill 运行器可输出四份带合法来源引用的结构化意见；失败时不伪造。
5. 共识门槛、bit浪浪执行主案和点位纪律按规格工作。
6. Binance 只读持仓可区分已证明的持仓状态；任何代码路径都不能真实下单。
7. Bark 可发送候选、确认、加仓候选、止盈观察和失效，并带本地/TradingView 链接。
8. 免费 TradingView 只需一个指标槽，指标可以复核平台、趋势线、量能和状态。
9. UI 能追溯形态锚点、行情快照、Skill 版本、R1/R2/R3/R4 和通知结果。
10. 新增测试、现有 `npm test`、`npm run lint` 和构建全部通过。

## 19. 明确不保证

- 形态出现不代表必然强势拉升。
- 四专家一致不等于客观胜率，也不保证点位可成交。
- Bark 延迟、网络故障和 AI 运行时间可能导致价格离开候选区；离开后系统必须标记“不追”，不能追补点位。
- 回测、前向观察和模拟表现不能证明未来收益。
- 本系统第一版是研究和人工决策辅助，不构成自动交易授权。
