# 多模型供应商与币安广场情报集成设计规格

日期：2026-08-13  
状态：用户已逐节确认并授权编码  
产品边界：研究建议、提醒和模拟交易；不提供真实下单

## 1. 目标与交付顺序

在现有交易议会 MVP 中增加两个可独立运行的能力：

1. 建立统一模型网关，支持 OpenAI、Claude、DeepSeek 直连及 OpenCode Go DeepSeek。用户在设置页选择唯一的全局供应商；系统发现额度、限流、鉴权或连续超时后主动告警并暂停，绝不自动跨供应商切换。用户手动切换后，同一行情快照从未完成轮次继续。
2. 复用本机 `binance-square-monitor` 的 `/api/leaderboard`，展示市场热议币、情绪分布和“多数看空但价格抗跌”的空头拥挤候选；高可信候选发送 Bark 强提醒，但只建议立即研究，不自动调用专家、不创建模拟仓位。

实现顺序为：模型网关与设置中心 → 可恢复会诊 → 广场评分与页面 → 待触发模拟计划 → 通知重试和复盘基础。

## 2. 多模型供应商

### 2.1 支持范围

| Provider ID | 协议 | 默认地址 | 默认模型 |
|---|---|---|---|
| `openai` | Responses API | `https://api.openai.com/v1/responses` | `gpt-5` |
| `anthropic` | Messages API | `https://api.anthropic.com/v1/messages` | `claude-sonnet-4-5` |
| `deepseek` | OpenAI-compatible Chat Completions | `https://api.deepseek.com/v1/chat/completions` | `deepseek-chat` |
| `opencode_go` | Responses API | `https://opencode.ai/zen/go/v1/responses` | `deepseek-v4-flash` |

地址和模型均允许用服务端环境变量覆盖。所有密钥只存在服务端环境变量，不写数据库、不返回浏览器。

### 2.2 全局切换规则

- D1 保存当前全局 Provider ID；未保存时使用 `AI_PROVIDER`，再回退到 `openai`。
- 设置页显示四个供应商是否已配置、当前模型、最近错误和当前选择。
- 用户点击后只切换全局 Provider，不修改任何专家 Skill、Prompt 或交易规则。
- 不自动故障切换。供应商切换后只影响新请求及暂停任务的未完成部分。
- 同一场会诊允许混用供应商；每份意见保存实际 Provider、模型、耗时和尝试次数。

### 2.3 统一模型合同与错误分类

模型网关接受系统提示、用户输入和 JSON Schema，返回结构化 JSON、Provider、模型与用量元数据。供应商适配器负责各自协议，Expert Runner 只依赖统一接口。

错误归类为：

- `AUTH`：401/403 或无效密钥。
- `QUOTA`：余额不足、配额耗尽。
- `RATE_LIMIT`：429。
- `TIMEOUT`：连续三次超时。
- `TRANSIENT`：可在当前 Provider 内重试的 5xx/网络故障。
- `INVALID_OUTPUT`：无法解析或不符合 Decision Contract。

`AUTH`、`QUOTA`、`RATE_LIMIT` 和三次 `TIMEOUT` 令会诊进入 `PAUSED_PROVIDER_ERROR`；系统保存错误并发送一次 Bark 告警。`INVALID_OUTPUT` 只标记该专家失败，不触发跨供应商切换。

## 3. 可恢复会诊与幂等

- 日线会诊键固定为 `daily:{lastClosedDailyDate}:{symbol}`。同一闭合日线无论 1H 数据后来如何变化，都只产生一次日线会诊。
- 首次运行冻结 D/4H/1H 快照；恢复必须使用原快照，不能抓取新行情替换。
- Consultation 在模型调用前创建。R1/R2/R3 每一份有效意见立即保存为 checkpoint。
- 暂停后已经完成的意见不重算；继续时只执行缺失的专家/轮次。
- 任务租约带 fencing token；完成、失败或暂停更新只能由当前 token 持有者提交。
- 所有模拟账户副作用只在完整 R3 和 R4 完成后执行一次。

## 4. 币安广场情报

### 4.1 数据边界

`binance-square-monitor` 继续负责采集、去重与实时市场补全；网站服务端读取 `/api/leaderboard` 并标准化。采集服务不可用时，网站可回退 Binance 公开行情，但必须标记广场情绪缺失，不能生成高可信空头拥挤信号。

标准字段包括：1H/4H/24H 讨论量、有效作者数、热度增速、看多/看空/中性占比、价格变化、相对 BTC 强度、最大回撤、OI、资金费率、主动买卖比、清算及数据覆盖状态。

### 4.2 三类榜单

- 热议榜：讨论量、作者数和热度增速。
- 价格抗跌榜：看空占比至少 65%，帖子至少 20、作者至少 10；4H 不跌或显著强于 BTC，24H 回撤受控。
- 空头扛单/挤压候选：在价格抗跌基础上，OI 增加或高位维持，并由资金费率、主动成交或清算证据增强。

排除新上市、低流动性、异常插针及样本不足币种。只有舆情没有仓位证据时，最高为普通候选。

### 4.3 可解释评分

总分 100：看空情绪与样本 25、价格抗跌和相对 BTC 25、OI 与资金费率 20、主动成交和清算 15、结构突破 15。

- 0–49：不进入专属榜。
- 50–64：普通观察。
- 65–79：空头拥挤候选。
- 80–89：高可信空头扛单。
- 90–100：挤压触发候选。

每个结果必须展示分项得分、有效样本、支持证据、风险、数据缺失和失效条件。

### 4.4 强提醒

- 80 分首次发送 Bark；同币种 4 小时冷却。
- 冷却期间评分提高至少 8 分，或升级到 90 分挤压触发，可再次提醒。
- 文案使用“强烈建议立即研究”，禁止使用无条件买入措辞。
- 提醒不自动触发四专家、不创建模拟仓位。用户可从雷达页手动触发短线会诊。

## 5. 条件计划与模拟安全

- 专家计划增加机器可执行触发字段：触发类型、周期、入场区、收线阈值、止损、目标、分批比例、有效期和最大亏损。
- 无法结构化的计划只展示，不进入模拟盘。
- 未触发计划保存为 `PENDING`，由低成本市场轮询器检查；不在会诊后处理时永久丢弃。
- 保证金、费用、订单、成交、持仓在一个原子账务操作中写入；同账户同币种串行，最多一个方向仓位。
- 可用现金采用 free-cash 语义，不再次减去已从现金扣除的 isolated margin。
- 开仓前验证按止损距离计算的损失和手续费不超过 `maxLossUsdt`。
- 止损、止盈、失效与强平持续监控；强平损失不得穿透逐仓保证金。

## 6. 通知、复盘与学习

- 通知先持久化待发送状态，再调用 Bark。Provider 告警、空头扛单、模拟入场/退出、数据过期和每日任务失败分别使用稳定去重键。
- FAILED 通知由独立重试任务扫描，不依赖用户重复触发原会诊。
- 每日复盘已结束或已有足够后续走势的计划；每周/月按专家、市场状态、币种、周期和信心区间统计。
- 方向判断、执行纪律和最终结果分开评分。
- 原始 Skill 永久只读；反复验证后的候选经验进入可撤销、有版本的 Overlay，不因单次盈亏自动晋级。

## 7. 页面

- `/settings`：模型中心、连接测试、全局切换、当前故障与“继续暂停会诊”。
- `/`：热议币摘要、最高空头扛单候选和模型健康告警。
- `/radar`：完整热议榜、情绪、相对 BTC、OI/资金费率、分项评分、历史与手动短线会诊入口。
- `/consultations`：每份意见显示 Provider/模型，暂停会诊显示断点和继续状态。
- `/arena`：待触发计划、持仓、止损止盈、实际权益和盘中最大回撤。

## 8. 测试与验收

- 四种协议的请求构造、响应解析、错误分类与密钥不泄露测试。
- 全局切换只影响未完成请求；混合 Provider 会诊可追溯。
- 同一日跨 1H 收盘重复调用不创建第二次会诊。
- 暂停后恢复不重算已保存 checkpoint，也不替换快照。
- 热议、抗跌、拥挤、高可信和挤压触发各阈值与数据缺失降级测试。
- Bark 冷却、8 分升级、90 分升级和失败重试测试。
- 模拟账务原子性、单币种串行、free-cash、止损风险、止盈和逐仓清算测试。
- 页面在桌面和 390px 宽度无横向溢出；DEMO、缺配置、暂停和上游不可用均有明确标记。
- 全库不得出现 Binance 真实下单 POST/DELETE 路由，所有相关响应继续返回 `realOrderRouteEnabled: false`。
