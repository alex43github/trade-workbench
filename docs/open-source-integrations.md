# 开源交易工具整合参考

更新时间：2026-09-07

本文档记录交易工作台后续需求应优先检查的开源项目。它们是外部参考和可选整合来源，不代表已经安装、启用或获得生产授权。每次新增行情、链上数据、策略、执行或监控需求时，先查本清单和对应 GitHub 仓库，再决定是复用、适配、旁路运行，还是继续使用现有实现。

## 评估顺序

1. 先确认需求属于数据、链上交互、策略研究、交易执行还是可观测性。
2. 查询下表对应仓库的当前文档、许可证、维护状态、支持范围和安全边界。
3. 对照现有网站能力，优先复用稳定的数据模型或适配层；不要为了“统一框架”替换已经满足需求的 Binance Gateway、模拟盘或风险闸门。
4. 先使用只读、缓存、测试网或 dry-run 方式验证；涉及真实订单、签名交易、提现或资金移动时，必须单独经过安全设计和用户明确确认。
5. 记录选择理由、版本/提交、配置项、降级路径和验收结果。若只是借鉴思路而不引入代码，也要在对应需求文档中说明。

| [Dune Skills](https://github.com/duneanalytics/skills) | 链上数据与 Agent Skills | 钱包、Token、交易、Holder、DeFi Position、数据集或 Query 管理 | 服务端链上数据适配器、雷达数据快照、研究工具 | 新的链上数据需求优先检查；查询结果必须带时间戳、来源和缓存状态，不直接作为下单信号 |
| [CCXT](https://github.com/ccxt/ccxt) | 多交易所统一行情/API | 多交易所价格、K线、订单簿、成交、Funding、账户或价差 | 只读行情/研究适配层；多交易所需求的候选统一接口 | 可用于研究和公共数据；Binance 私有执行仍以现有 Gateway、订单策略和审计链为准，不因引入 CCXT 绕过安全闸门 |

| [Prometheus](https://github.com/prometheus/prometheus) | 运行监控与告警 | WebSocket 最后消息、RPC 延迟、API 错误、扫描次数、Signal、订单失败、余额和 PnL | 网站/网关/扫描器的 metrics 与外部监控 | 24 小时运行需求优先检查；指标不得暴露密钥、完整订单敏感信息或用户隐私，告警要有明确处理动作 |
| [Hummingbot](https://github.com/hummingbot/hummingbot) | DEX、做市、套利 | 做市、跨所套利、DEX 自动交易、Gateway 连接 | 独立 worker 或专用服务，不嵌入 Next.js 请求链 | 只有出现明确做市/套利需求才评估；先 paper/dry-run，独立风控、限额、熔断和密钥隔离 |
| [Freqtrade](https://github.com/freqtrade/freqtrade) | CEX 策略、回测、dry-run、实盘 | 策略回测、参数优化、仓位管理、WebUI、Telegram 控制 | 策略研究/回测旁路，或经过适配的策略运行器 | 可复用回测和 dry-run 思路；不得让其绕过本网站的模拟盘、风险评分、人工确认和实盘锁 |
| [NautilusTrader](https://github.com/nautechsystems/nautilus_trader) | 重型事件驱动交易引擎 | 多市场、多策略、高并发、订单状态和回测/实盘一致性 | 独立研究/执行服务 | 当前 MVP 不默认引入；只有现有架构无法满足复杂事件驱动或多市场执行时再做专项方案 |

## 与现有架构的边界

- 网站的 Next.js 页面只消费经过服务端校验、标准化和脱敏的数据；外部项目不得直接从浏览器访问私有 API、RPC 私钥或交易所签名接口。
- Binance Gateway 继续负责 Binance 私有接口、订单策略、幂等、审计和真实交易开关。CCXT、Hummingbot 或 Freqtrade 如果被采用，只能通过明确的服务适配层接入。
- Dune、web3.py 和其他链上来源用于发现、验证和研究；数据延迟、缺失、链重组、RPC 错误或查询失败时，必须显示 degraded/unknown，不得伪装成确定性信号。
- Prometheus 只负责观测和告警，不负责策略判断或订单执行；监控异常不能自动扩大权限或自动重试高风险订单。
- 所有真实交易能力继续遵守项目红线：默认关闭、用户明确确认、服务端复核、精度校验、限额/熔断、可追踪订单状态和可恢复失败。

## 不采用的默认理由

当现有实现已经满足需求时，不为了“技术栈看起来更完整”引入大型框架。尤其不要在没有明确多交易所、做市、DEX、并发或回测一致性需求时引入 Hummingbot、Freqtrade 或 NautilusTrader。引入前必须说明维护成本、部署拓扑、数据一致性、故障恢复和真实交易风险。
